# Portkey

> 一把钥匙，开门即达。

把局域网里的服务（网站、远程桌面、数据库、任意 TCP 端口）通过 SSH 隧道发布到公网。绿色版、一键启动、自带图形界面，**服务器上不需要安装任何软件**。

```
外部访问者              你的服务器（公网 IP）           内网电脑
    │                        │                          │
    │ ① 访问 域名:8080       │                          │
    ├───────────────────────►│                          │
    │                        │ ② 通过已建立的 SSH 隧道   │
    │                        ├─────────────────────────►│
    │                        │                          │ ③ 连接内网服务
    │                        │                          ├──► 192.168.1.50:80
    │ ④ 响应原路返回          │                          │
    │◄───────────────────────┤◄─────────────────────────┤
```

## 为什么是 Portkey

| | Portkey | frp | ngrok / 花生壳 |
|---|---|---|---|
| 服务端是否要装东西 | **不用**，只借 SSH | 要装 frps | 用第三方中继 |
| 图形界面 | ✅ 自带 | ❌ 配置文件 | 部分 |
| 自动配置服务器 | ✅ 自动改 sshd、放行防火墙 | ❌ 手动 | — |
| 流量是否经过第三方 | **不经过**，直连你自己的服务器 | 不经过 | 经过 |
| 是否需要公网 IP | 需要（你自己的服务器） | 需要 | 不需要 |
| 免费 | ✅ 完全免费 | ✅ | 有限额 |

核心思路：**借用服务器上本来就有的 SSH，不装任何东西**。客户端主动连出去（出方向，运营商和 NAT 都不会拦），连上后在服务器上开一个公网端口，外部流量顺着这条已建立的连接倒灌回内网。

## 特性

**连接**
- SSH 反向隧道，服务器零安装
- 一键连接：自动修改 sshd 配置（`GatewayPorts` / `AllowTcpForwarding`）、自动放行 `ufw` / `firewalld` / `iptables`、自动校验配置（出错回滚）
- 断线自动重连，重连后自动重建全部端口映射
- 支持密码登录与私钥登录；非 root 用户支持 sudo 密码
- 单实例保护：重复启动只会把已有窗口拉出来

**端口映射**
- 界面增删改，实时生效，无需重启
- 自动识别服务类型（网页 HTTP/HTTPS 与其他 TCP），避免对远程桌面等服务显示错误的网页链接
- 每个映射独立的流量与连接数统计
- 内网地址可填同网段其它机器，那台机器无需安装任何东西

**监控**
- 实时速率曲线（下载 / 上传）
- 服务器资源面板：CPU、内存、磁盘、负载、网卡速率、运行时长
- 分级运行日志，可按「信息 / 警告 / 错误」筛选

**其他**
- 深色模式（首次跟随系统）
- 断线桌面通知
- 配置导入导出（凭据用 scrypt + AES-256-GCM 加密）
- 本地凭据 AES-256-CBC 加密存储，配置损坏自动备份并重建

## 快速开始

### 方式一：下载绿色版（推荐）

到 [Releases](../../releases) 下载压缩包，解压后双击 `启动.bat`。

绿色版自带 Node.js 运行时，无需安装任何环境。

### 方式二：从源码运行

需要 **Node.js 18+**。

```bash
git clone https://github.com/<你的用户名>/portkey.git
cd portkey

# 安装依赖
cd app && npm install && cd ..

# 启动
node app/src/main.js
```

Windows 上也可以直接双击 `启动.bat`（会自动使用系统安装的 Node.js）。

### 开始使用

1. 在「服务器」页填入公网 IP、SSH 端口、用户名、密码，点 **测试连接** 验证账号密码
2. 点 **一键连接** —— 程序会自动登录服务器、改好 sshd 配置、放行防火墙并建立隧道
3. 在「端口映射」页填入内网端口和公网端口，点 **添加映射**
4. 访问 `http://你的域名:公网端口`

> ⚠️ **别忘了在云服务器控制台的安全组里放行公网端口** —— 安全组属于云平台，SSH 改不了。

## 安全说明

- **本地凭据加密存储**：密码用 AES-256-CBC 加密后保存在 `app/data/config.json`，密钥在同目录 `.key`。**整个 `app/data` 目录不要外传**；不勾选「记住密码」则完全不落盘。
- **管理界面只监听 `127.0.0.1`**：外部无法访问你的本地控制台。
- **修改 sshd 前会先备份**：原文件备份为 `/etc/ssh/sshd_config.portkey.bak`，且写入后会用 `sshd -t` 校验，出错自动回滚。
- **流量不经过任何第三方**：只走你自己的服务器。
- **远程桌面请勿直接暴露**：3389 暴露公网容易被爆破，建议映射到高位端口并使用强密码，或改用 WireGuard / Tailscale 等组网方案。

## 常见问题

**Q：连接提示"连接超时"？**
检查服务器 IP、云安全组是否放行 SSH 端口（默认 22）、服务器防火墙是否放行。

**Q：提示"端口被服务器拒绝：sshd 未开启 AllowTcpForwarding 或 GatewayPorts"？**
点「重新配置服务器」重试；若仍失败，通常是非 root 用户没有填 sudo 密码。

**Q：显示"已开放"，但外网访问不通？**
按顺序排查：① 云控制台安全组是否放行该端口；② 映射的内网地址端口是否正确（用「探测」按钮验证）；③ 服务器上是否有其它程序占用该端口。

**Q：内网服务在另一台机器上，那台机器也要装吗？**
不用。内网地址填那台机器的 IP（如 `192.168.1.50`）即可，前提是运行 Portkey 的这台机器能访问到它。

**Q：停用或删除映射后端口没释放？**
SSH 协议不支持单独取消某个转发端口。页面顶部会提示「重启隧道以释放端口」，点一下即可。

**Q：服务器在国内，用 80/443 需要备案吗？**
需要。使用 8080、33890 等非标准端口不受影响。

## 开发

### 目录结构

```
.
├─ 启动.bat / 停止.bat     绿色版一键启停脚本
├─ app/
│  ├─ src/
│  │  ├─ main.js           启动入口：本地服务 + 拉起窗口
│  │  ├─ ssh.js            SSH 会话（连接、执行命令、请求端口转发）
│  │  ├─ provision.js      服务器自动配置（sshd、防火墙）
│  │  ├─ tunnel.js         隧道管理（转发、重连、统计、资源采集）
│  │  ├─ web.js            本地 HTTP 接口
│  │  ├─ config.js         配置读写与凭据加解密
│  │  └─ logger.js         日志
│  └─ public/              前端界面（原生 HTML/CSS/JS，无框架）
└─ tools/                  测试套件
```

技术栈刻意保持极简：**后端只有 `ssh2` 一个依赖，前端零依赖、零构建**。
